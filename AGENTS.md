# Portfolio Site

## Stack

- Next.js 16.4.3 App Router (Turbopack), React 19, TypeScript (strict), Tailwind CSS 4.
- `next.config.ts` enables `cacheComponents`, `partialPrefetching`, and `experimental.agentFeedback`. Check `node_modules/next/dist/docs/01-app/` before using unfamiliar Next APIs.
- Single app at the repo root, no `src/`; `@/*` maps to the root (`@/components/...`, `@/data/...`).
- No test runner or test files. Don't add or assume one unless asked.

## Commands

Use npm (`package-lock.json` is the only lockfile).

- `npm run dev` — dev server on port 3000.
- `npm run build` — production build; also runs the TypeScript check and prerenders all routes.
- `npm run start` — serve the production build (run `npm run build` first).
- `npm run lint` — ESLint over the repo. Single file: `npx eslint app/page.tsx`.
- `npx tsc --noEmit` — standalone typecheck. It can exhaust the default Node heap; if it OOMs, raise it (`$env:NODE_OPTIONS="--max-old-space-size=4096"` in PowerShell) or rely on `npm run build`.

## Architecture

- `app/page.tsx` composes the homepage from section components in `components/`. Sections are self-contained; no shared layout beyond `app/layout.tsx`.
- `app/projects/[slug]/page.tsx` is the only dynamic route. Params are async in this version: `const { slug } = await params`. Keep that shape, and keep `generateStaticParams` fed by `getAllProjectSlugs()`.
- All portfolio content is data-driven:
  - `data/personal.ts` — identity, contact, socials, bio, skills, education.
  - `data/projects.ts` — projects. Appending to `projectsData` automatically produces the detail page, sitemap entry, project card, and prev/next links. Keep `slug` stable (it is the public URL), put images in `public/images/`, and reference them as `/images/<file>`.
  - Adding a field to a project requires updating the `Project` interface in the same file. `Project["category"]` is a union; extend it when adding a new category.
- Contact form is client-only and opens a `mailto:` link. There is no backend, API route, or database in this repo.
- `"use client"` is only on interactive components (`Navbar`, `Hero`, `Skills`, `ProjectsSection`, `ContactSection`, `Footer`, `ProfileImage`, `ResumeNoticeModal`). Keep pages, layout, data, and static sections as server components.

## Styling

- Tailwind 4 is CSS-first: no `tailwind.config.*` and no PostCSS config. `app/globals.css` holds `@import "tailwindcss"` and the theme variables. The Turbopack CSS loader is wired up in `next.config.ts`.
- Reuse the custom utilities in `app/globals.css`: `.glass-panel`, `.glass-panel-hover`, `.gradient-text-purple`, `.gradient-text-cyan`, `.gradient-text-hero`, `.bg-grid-pattern`.
- Dark-only theme: background `#060913`, card `#0d1224`, accents violet `#8b5cf6` and cyan `#06b6d4`. Match the surrounding utility-class style rather than adding new CSS files.

## Gotchas

- The site URL `https://riyad-portfolio.vercel.app` is hardcoded in `app/layout.tsx` (`metadataBase` + Open Graph), `app/robots.ts`, and `app/sitemap.ts`. Update all three when the domain changes. `sitemap.ts` also hardcodes `lastModified` to `2026-10-29`.
- No environment variables are required; the project deploys to Vercel as-is.
- `ProfileImage` requests `/profile.jpg` and falls back to `/images/avatar-placeholder.svg` on error; keep the fallback if the photo is replaced or removed.
- The resume CTA opens `ResumeNoticeModal` (intentional placeholder, not a broken link); LinkedIn is driven by `personalData.socialLinks.linkedin`.
